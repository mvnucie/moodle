How can I view a student’s activity using Moodle logs?

Back to Moodle FAQ

Moodle Logs record a time-stamped event for virtually every click that reaches Moodle, including page views, submissions, updates, and other actions. This makes Logs the most detailed course report for reconstructing what Moodle received from a student and when it occurred.

That detail can also make Logs difficult to interpret. They work best for investigating a specific question about one student, activity, or time period rather than for a quick overview of the entire class.

When to Use Logs

Use Logs when you need to:

  • confirm whether and when a student entered the course or opened a particular activity;
  • determine whether Moodle recorded an attempt, submission, update, or other action;
  • review the sequence of events around a deadline or reported problem; or
  • trace what the student did immediately before an error or unexpected result.

Important: A log entry shows that Moodle recorded an event. A page view does not prove that the student read the page or how long it remained open. If an expected event is missing, the Logs show that Moodle did not record it, but they do not necessarily explain why.

View a Student’s Logs

  1. Open the Logs Report

    Open the Moodle course you want to investigate. From the course toolbar, follow:

    Reports → Logs

  2. Select the Student and Date

    In the participant menu, select the student whose activity you want to review. Then choose All days or a specific date.

    Start with the smallest useful time period. A single day can still contain many entries, especially if the student was active throughout the course.

  3. Narrow the Report

    Use the remaining menus only when they help answer your question:

    • Activity: Select one assignment, quiz, forum, resource, or other course item to see events connected to it.
    • Actions: Limit the report to actions such as viewing, creating, updating, or deleting.
    • Sources and Events: These can generally be left at their default settings.

    If you are unsure which filter contains the event you need, leave that menu at its broadest setting and narrow the results after the first search.

  4. Generate the Report

    Select Get these logs. Moodle displays the matching events with the newest entries first.

    If the report is still too broad, adjust the filters and run it again. You can also use the download controls below the results to save the report for closer review.

Interpret the Results

Each row represents one event recorded by Moodle. The most useful columns are:

  • Time: When Moodle recorded the event.
  • Event context: The course, activity, or area connected to the event.
  • Event name: The type of action Moodle recorded.
  • Description: A sentence identifying the user, action, and affected item.
  • Origin: How the event reached Moodle, such as through the website.
  • IP address: The network address used for the request. It may provide supporting context, but it is not a precise or reliable physical location.

Read the Event name and Description together, then compare nearby rows. A sequence of events is usually more meaningful than one isolated entry. For example, viewing an assignment is different from Moodle recording a submitted assignment.

If you need to investigate a disputed submission, access problem, or complicated sequence of events, contact the Center for Innovative Education. Include the course, student, activity, and approximate date and time so CIE can help filter and interpret the Logs.
